# Blind mode: Double Blind inside Glow (X1 backend, X2 iPhone, in parallel)

**Decision (David, 2026-10-25): one app, two modes.** Glow stays the core (Rooms: people in the same place, secret mutual tap, the glow). Double Blind becomes a second mode, **Blind**, in the same app, on the same account, profile, photos, blocks, server and database. The demo is very soon: build the stage path first, commit early and often, never leave main broken.

## What Blind mode is

You opt in. You swipe on other Blind members' photos only (no names, no bios). Mutual right swipes become hidden matches. Nothing is shown until a "drop" opens all your waiting matches at once as blind chats with random codenames (Fox, Comet). You chat without knowing which of the people you liked it is. Reveal shows name and photos only when both tap. Either side can leave without ever being revealed.

Source of truth for behaviour: the working Double Blind codebase at `/Users/davidxie/Desktop/Projects/double-blind` (read only, never edit it). It passed its full test suites and a two-Simulator end-to-end loop. Read its `docs/SPEC.md` (blindness invariants B1 to B12), `docs/DECISIONS.md`, `docs/SECURITY.md` (F-01 and the DEMO_MODE decision) and `docs/HANDOFFS.md` for the details below.

## Mapping decisions (already made; do not re-litigate, note any unavoidable change in docs/DECISIONS.md)

1. **Opt-in.** New table `blind_members(user_id pk -> profiles, joined_at, paused bool)`. Only members appear in the Blind deck or can swipe. `POST /api/blind/join`, `DELETE /api/blind/join` (leaving deletes your Blind swipes, matches and chats). The opt-in screen says plainly: "Your photos (never your name) are shown to other Blind members. Nothing about rooms or where you are is ever shown."
2. **Profile and photos come from Glow.** Name = `profiles.first_name`; age from `birthdate`; `gender` and `show_me` decide compatibility both ways; `paused` and `banned_at` exclude; card photo = the member's first `profile_photos` row with `moderation_status = 'approved'` (lowest position). Sign them with Glow's existing private-image signing (60 s links); never public links.
3. **Glow's privacy invariant P1 applies to Rooms, not to the Blind deck.** In Blind mode a member's face photo is shown before a match (that is the product), but never their name, ID, room, check-in or location. Blind deck and Guess Who card ids must be **opaque per viewer** (not Glow user ids): store `blind_cards(viewer, card_id uuid, target)` when serving the deck and resolve swipes through it. Before mutual reveal, nothing about a Blind chat partner (id, name, photo, room) may reach the phone (Double Blind's B1).
4. **Blocks are Glow's `public.blocks`**: a block from a Blind chat blocks that person everywhere, both modes, both ways. Reports go into Glow's `public.reports` with a new `report_context` value for Blind chats (add the enum value in a migration) and `context_id` = the blind chat id.
5. **Blind tables are prefixed `blind_`**: `blind_members`, `blind_cards`, `blind_swipes`, `blind_matches`, `blind_chats`, `blind_messages`, `blind_drops`, `blind_drop_seen`, `blind_chat_exits`, `blind_codenames`, `blind_codename_uses`. Port Double Blind's SQL functions (record_swipe with the 20/day cap and pair advisory lock, deck_for, run_drop, run_drop_before, run_drop_all, drop_new_chats, chat_list_for, list_messages, send_message, tap_reveal, leave_chat, block via Glow blocks, pool_cards, record_guess) as `blind_*` functions, security definer, fixed search_path, service role only, following Glow's lockdown rules (Glow's lockdown pgTAP must still pass).
6. **API under `/api/blind/*`**, same request and response shapes as Double Blind's contract (`web/lib/contract/index.ts` and `contracts/examples/*.json` in the Double Blind repo) except ids are the opaque card ids and paths are prefixed: `GET /api/blind/me` (membership, rightRemaining, rightCount, canDrop), `POST|DELETE /api/blind/join`, `GET /api/blind/deck`, `POST /api/blind/swipe`, `GET /api/blind/pool`, `GET /api/blind/pool/cards`, `GET|POST /api/blind/drop`, `GET /api/blind/chats`, `GET /api/blind/chats/{id}`, `GET|POST /api/blind/chats/{id}/messages`, `POST /api/blind/chats/{id}/reveal`, `/leave`, `/guess`, `/block`, `/report`, plus admin "drop for everyone" in Glow's admin and the cron route. Add them to Glow's `contracts/openapi.yaml` (operationIds prefixed `blind`), run `scripts/codegen.sh`, and use Glow's route helper. Port `leak-check.ts` (the give-away warning; regex first, optional Claude pass, regex fallback). Not-allowed is 404 (Glow P11).
7. **Instant drop for the stage**: server env `BLIND_DEMO_MODE=true` opens drops immediately; otherwise only after the nightly drop time (8pm Pacific), with Double Blind's F-01 cutoff (`run_drop_before`). Document it as stage-only.
8. **App structure**: a fourth tab **Blind** next to Rooms, Matches and Settings (Glow's `MainTabs` in `ios/Glow/Navigation/RootView.swift`). Inside it: opt-in screen, then deck, drop, blind chats list, chat, reveal, Guess Who, report. All new UI lives in a new GlowKit module `FeatureBlind` (depends only on AppCore and DesignSystem, like every Glow feature module), using Glow's DesignSystem tokens and components so it looks like one app. Port the views and view models from Double Blind's `ios/Packages/DBKit/Sources/{Deck,Drop,Chat,Safety}` (gestures, image store, drop animation, polling chat, give-away sheet, reveal sheet and screen) and restyle them. Routes: add `.blind`, `.blindDrop`, `.blindChat(BlindChatID)`, `.blindReveal(BlindChatID)`, `.blindGuess(BlindChatID)`, `.blindReport(BlindChatID)` to AppCore's `Route`.
